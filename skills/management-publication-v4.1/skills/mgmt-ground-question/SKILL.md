# Ground One Publishable Question

Produce a paper thesis, not a list of possible gaps.

## Step 0 — Do not fabricate the literature

Read [references/source-honesty.md](references/source-honesty.md).

If current scholarly knowledge is required, search and verify before naming specific papers or claiming a gap.

## Step 1 — Define the research object before the field

Read [references/research-object-card.md](references/research-object-card.md).

Write five lines:
1. **Reality object** — what is happening in the real world?
2. **Academic object** — what construct/process might scholarship call it?
3. **Data object** — what does the available data literally record?
4. **Candidate construct** — what do we want to infer?
5. **Not equal to** — what tempting stronger construct is not directly observed?

Do not search for a literature using a label that has not survived this step.

## Step 2 — Map the academic mountain, not a bibliography

Read [references/field-map.md](references/field-map.md).

Establish:
- the primary scholarly conversation;
- its central question;
- stable knowledge;
- genuine disagreements or unresolved bottlenecks;
- important authors/groups and foundational work;
- the recent frontier;
- common data and methods;
- adjacent literatures that are not equivalent.

A field map is not complete until you can answer:

> If this paper were published, which existing papers would it directly talk to?

## Step 3 — Require a verified substantive anchor

Read [references/anchor-ledger.md](references/anchor-ledger.md).

A full unpositioned project cannot become `POSITIONED` without at least one verified `SUBSTANTIVE` anchor, unless the user has already supplied and established it.

Method, theory, and style papers cannot substitute for a substantive anchor.

If the closest substantive anchor is not yet known, stop the thesis freeze and perform the search/deep read first.

Use `$mgmt-reverse-engineer-paper` when a candidate anchor is found.

## Step 4 — Establish the problem origin

Allow only defensible routes:
- competing explanations/findings;
- accepted belief with weak systematic evidence;
- measurement/data/identification bottleneck;
- important boundary condition;
- a practice puzzle that maps to an existing scholarly problem.

"Few studies", "new dataset", "first use of AI", and "significant result" are not sufficient problem origins.

## Step 5 — Run a frontier collision scan before freezing novelty

Read [references/frontier-collision.md](references/frontier-collision.md).

Search recent work around:
- same X;
- same Y;
- same mechanism;
- same context;
- same proposed delta.

If the delta already exists, redefine it. Do not hide collision evidence.

## Step 6 — Freeze one core RQ and one primary novelty delta

The paper should normally answer one core question.

Choose one primary delta:
- new/better data that resolves a known limit;
- new theory/mechanism;
- new identification;
- new measurement;
- important boundary/context.

Do not claim all of them unless evidence truly supports each.

## Step 7 — Freeze the belief update

Write:
- **BELIEF_BEFORE** — what a reasonable reader of the field would believe without this paper.
- **BELIEF_AFTER** — what the evidence could make that reader update.

If Before ≈ After, the topic may not yet justify a paper.

## Step 8 — Bridge the big problem to the evidence

Read [references/big-problem-bridge.md](references/big-problem-bridge.md).

The chain must be continuous:

`Big problem → academic mechanism → core construct → available evidence`

If it breaks, reduce the "big" claim rather than adding rhetoric.

## Step 9 — Make a publication decision

Choose:
- `KEEP`
- `PIVOT`
- `SPLIT`
- `EXIT`

EXIT is a successful outcome when the field is saturated or the available data cannot answer the claimed question.

## Shared state

If `PAPER_STATE.md` exists, read it first and do not silently change frozen fields. For a new broad project, write/update the state only after the object, substantive anchor, and thesis are defensible.

## Deliverable

Return:
- Research Object Card
- Academic Mountain
- Anchor Ledger
- Problem Origin
- Frontier Collision result
- One Core RQ
- Primary Novelty Delta
- Belief Before / After
- 3–5 evidence steps
- KEEP / PIVOT / SPLIT / EXIT
- Existing assets: MAIN / SUPPORT / APPENDIX / SEPARATE PAPER / DROP

## Project memory integration

For a continuing research project, read [references/project-memory.md](references/project-memory.md).

**Read:** `PAPER_STATE.md`; `CONCEPT_LEDGER.md`; `LITERATURE_LEDGER.md`; `FAILURE_MEMORY.md`.

**Write/update:** `Research Object / Academic Position / Core RQ / Novelty Delta in PAPER_STATE.md after they are defensible`; `LITERATURE_LEDGER.md`; `RUN_LOG`; `FAILURE_MEMORY.md for positioning failures`.

**Constraint:** Do not freeze a paper thesis without a verified substantive anchor for an unpositioned project.
